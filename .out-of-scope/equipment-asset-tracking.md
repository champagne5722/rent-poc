# 設備資產個體管理

這個專案不追蹤單一設備的個體資料。不記錄序號、採購日、維修史、目前所在物件，也不做跨物件調度。

## 為什麼不做

平台管理的單位是租賃單位、案件與合約。設備在這裡只有兩個用途：

- 合約的設備附件，列出「項目加數量」。
- 點交時逐列對照，確認項目還在、狀況如何。

這兩個用途只需要設備詞彙庫與數量。目前的型別就是這個形狀：

```ts
// 設備清單的一列：詞彙庫項目加數量
export interface EquipmentItem {
  name: string;
  quantity: number;
}
```

資產個體管理是另一個 bounded context。它需要自己的資料模型（個體、位置異動、維修工單的關聯）、自己的畫面與自己的權限。它服務的工作是「庫存與折舊」，不是「出租與簽約」。把它做進來，物件與合約兩個模組都要認得個體，設備附件與點交對照也要改成以個體為單位。

三階段路線裡的「全資產清冊」指的是不動產資產，不是家電。所以這個功能不在任何一個階段的範圍內。

## 相關決定

- ADR-0008：三層文件組裝，設備以詞彙庫項目加數量進入合約。
- 修繕紀錄（P0-16）記錄的是案件上的報修事件，不綁定設備個體。

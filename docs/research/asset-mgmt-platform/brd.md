## 1. 導入：情境、變化、問題、答案

**情境。** 台灣的不動產服務依牌照切成四段：仲介做買賣與媒合，代管業做收租與修繕，地政士做登記，銀行做信託。屋主要管多間房子，必須同時面對四種服務商，自己用試算表或 LINE 串起來。3 戶以上的非自住屋主約 4.1 萬人【中】，淨資產 1 億元以上的高資產者約 12.3 萬人【中】。

**變化。** 三件事同時發生。第一，房仲開始往代管走：住商 2026-04 設新品牌跨足包租代管，永慶首頁已有代租代管【中】。第二，銀行開始往管理走：至多六家公股銀行與力興資產簽信託加包租代管的轉介合作【中】。第三，監管收緊：兆基事件後，內政部研議押金專戶與業者退場機制【中】。每一方都在補自己缺的那一塊，但調查範圍內沒有任何一家把六塊服務放進同一個屋主入口。六塊是物件管理、租賃管理、買賣、履保或信託、資產總覽、稅務與傳承。

**問題。** 誰能給屋主一個入口，把這六塊串起來，而且不踩到四種牌照？

**答案。** rent-poc 擴展成屋主的不動產資產管理平台。平台做資料與協作層：物件、合約、款項狀態、文件、提醒、報表。執行交給持照網路：經理人、經紀業、代管業、地政士、銀行、建經。平台不持有資金、不居間、不代管。三階段推進，每階段有關卡：Phase 1 物件管理與租賃，Phase 2 物件銷售與信託帳戶，Phase 3 全資產管理。

## 2. 核心訊息與三個支撐

**核心訊息。** 整合入口在台灣仍是空白，平台應以「不持牌照的協作層」切入，先用租賃驗證屋主付費，再用買賣與傳承擴大單客收入。

| 支撐 | 證據 | 信心 |
|---|---|---|
| 一、供給面空白 | 七家仲介集團、信託銀行、包租代管業者、軟體商，調查範圍內沒有六塊合一的入口。國外有先例：Roofstock 整合買、管、賣與資產儀表板；東急リバブル租賣同窗口；Foxtons 三塊交叉銷售 | 【中】 |
| 二、牌照邊界清楚 | 不持有資金、不居間、不代管，平台不需牌照。經紀業加掛代管營業項目程序不難，信託業牌照才是高牆。這代表平台的對手會從仲介與銀行來，而且平台不能自己做金流 | 【高】 |
| 三、Phase 1 撐不起公司，Phase 2 與 3 才有單客收入 | Phase 1 SAM 約 8.4 億至 14.7 億元【低】，每位屋主年費約 2.85 萬元【低】。Phase 2 每案履保費行情約萬分之六。Phase 3 高資產者的資產管理費池天花板 40 億至 242 億元【低】 | 【低】 |

**最大風險。** 屋主需求只有供給端訊號，沒有屋主調查【高】。經理人或平台向銀行查帳沒有法源【高】。這兩項在 Phase 1 結束前必須用訪談與銀行書面回覆補上。

方向由使用者定，調研只找風險與配套。

| 編號 | 方向 | 風險等級 | 主要風險 | 配套 |
|---|---|---|---|---|
| D1 | 切入點：資產管理＋買賣＋租賃整合給屋主 | 中 | 仲介與銀行已用轉介組合，屋主需求未驗證 | 定位為協作層，執行交持照者。對外寫「調查範圍內未發現」 |

| D3-2 | Phase 2 物件銷售與信託帳戶 | 高 | 居間須經紀業許可；成交量下滑；履保費薄 | 與經紀業及地政士合作，由經紀人簽章。信託交銀行或建經 |

| D4 | 經理人驗證證照與身分 | 中 | 無照者接案，平台被追連帶責任 | 開通前驗證。標章寫「證書資料已核對」。依效期重驗 |
| D5 | 信託帳戶委託外部信託，外部查帳 | 高 | 查詢者只有買賣方本人，沒有經理人角色 | 維持 Phase 2。平台當特約通路。委託人書面授權指定經理人（須銀行確認） |

## 4. 客群與工作（JTBD）

| 客群 | 規模 | 要完成的工作 | 現在怎麼做 | 平台給的 |
|---|---|---|---|---|
| 多屋者（3 戶以上） | 41,188 人【中】，5 戶以上 8,388 人 | 「我要知道每間房子的租約、押金、收租、修繕狀況，退租時算得清楚」 | 試算表、LINE、委託代管 | 物件與單位清冊、合約、押金台帳、對帳、報表 |
| 經理人（代管業、經紀業） | 租賃住宅服務業 2,254 家【中】；經紀業未計 | 「我要向屋主證明我做了什麼、錢沒混用，而且接案時不違規」 | 自家系統或 Excel，證照靠紙本 | 證照驗證標章、屋主報表、簽章分流、移交包 |
| 承租人 | 隨單位數 | 「我要確認房東有權出租，押金不會消失」 | 自保 | 出租權源標示、合約查閱、押金狀態 |
| 買賣當事人（Phase 2） | 2025 年買賣棟數待取得 | 「我要知道錢在哪、流程到哪、誰在等我」 | 建經 App、仲介電話 | 案件狀態、文件待辦、查帳連結 |
| 高端客戶與家族（Phase 3） | 淨資產 1 億元以上 12.3 萬人【中】 | 「我要一份完整的資產清冊，到期與繼承不漏掉」 | 私銀、家辦、會計師，各自為政 | 全資產清冊、期限提醒、文件保管、持照者協調 |

甲方與乙方依契約類型定義：

| 契約 | 甲方 | 乙方 | 依據 |
|---|---|---|---|
| 租賃契約 | 出租人（屋主或包租業） | 承租人 | 內政部住宅租賃契約書範本 |
| 買賣契約 | 買方 | 賣方 | 內政部成屋買賣契約書範本 |
| 委託管理契約 | 委託人（屋主） | 受託人（代管業） | 租賃條例 §32 第 1 款 |

經理人是角色統稱，不是法定名詞。平台顯示法定稱謂：租賃住宅代管業者、包租業者、不動產經紀業者。資料模型拆成執業主體（公司或商號）與執業人員（自然人）。

## 5. 商業模式畫布

| 區塊 | 內容 |
|---|---|
| 客群 | 多屋者；經理人（代管業、經紀業）；承租人（免費）；Phase 2 買賣當事人與地政士、建經；Phase 3 高端客戶與信託銀行 |

| 通路 | 經理人帶屋主進來（B2B2C）；銀行信託部與力興類業者轉介；自有房源上架的 C 端入口（Phase 2 後） |
| 顧客關係 | 自助工具加經理人服務；高端客戶由持照合作方面對面 |
| 收入來源 | 見第 6 節 |
| 關鍵資源 | 產權錨點資料、持照者網路、合約與簽章能力（既有）、案件狀態機、法規函釋 |
| 關鍵活動 | 證照驗證、合約與文件流程、對帳與報表、持照者協調、合規維運 |
| 關鍵夥伴 | 點點簽；代管業與經紀業；地政士；銀行信託部；建經；產險（租金保障險）；內政部與數發部（憑證介接） |
| 成本結構 | 工程、法務與函詢、憑證與 API 介接費、客服與人工審核、持照者分潤 |

## 6. 收入模式

計費單位依競品經驗：台灣小房東戶數少，月費制比單位費易懂。國外主收入在附加服務，台灣需持牌通道，所以附加服務排在後面。

| 階段 | 收入來源 | 向誰收 | 單位 | 法規前提 |
|---|---|---|---|---|
| Phase 1 | 屋主訂閱 | 多屋者 | 每月，依單位數分級 | 無 |
| Phase 1 | 經理人訂閱 | 代管業、經紀業 | 每月，依管理單位數 | 無 |
| Phase 1 | 電子合約與簽章 | 屋主、經理人 | 每份 | 無 |
| Phase 1 | 物件驗證與謄本歸檔 | 屋主、經理人 | 每物件每次 | 使用者自行上傳謄本 |
| Phase 2 | 買賣案件流程費 | 經紀業、地政士、建經 | 每案件 | 與經紀業合作，由經紀人簽章 |
| Phase 2 | 特約通路分潤 | 建經 | 每案件 | 比照特約地政士加入建經通路 |
| Phase 2 | 自有房源上架 | 屋主 | 每筆固定費 | 不依成交計酬；灰區一函詢 |
| Phase 3 | 資產管理年費 | 高端客戶 | 每戶每年 | 只做清冊、提醒、文件、協調 |
| Phase 3 | 持照者轉介分潤 | 信託銀行、會計師、地政士、產險 | 每成交 | 保險分潤需保險代理或經紀資格 |

定價假設全部待訪談驗證，詳見財務模型的假設登記表：

| 項目 | 假設 | 參考 | 信心 |
|---|---|---|---|
| 屋主訂閱 | 每單位每月 50 至 80 元 | 每位屋主年費約 2.85 萬元反推（12,000 元租金、8% 費率、3.53 戶）【低】 | 低 |
| 經理人訂閱 | 每單位每月 30 至 60 元 | 好未來每間每月 10 元【低】；AppFolio 每單位每月 1.49 美元【高】 | 低 |
| 電子合約 | 每份 100 至 300 元 | 點點簽成本加流程價值 | 低 |
| 買賣案件流程費 | 每案件 1,000 至 3,000 元 | 履保費 2,000 萬成交約 12,000 元【低】 | 低 |
| 資產管理年費 | 每戶每年 3 萬至 10 萬元 | 遺囑信託簽約費 8 萬至 20 萬元【低】；AUM 費 0.1% 至 0.2%【低】 | 低 |

**單位經濟的結論。** 達到 1,000 萬元年營收，Phase 1 需約 351 位屋主客戶（12,000 元情境）【低】。SAM 相當於現有代管業營收的 43%，所以 Phase 1 的實際上限更低。Phase 1 是取得客戶與驗證付費的階段，公司的收入要靠 Phase 2 案件費與 Phase 3 高端客戶。

## 7. 產業五力摘要

| 力量 | 強度 | 說明 |
|---|---|---|
| 既有競爭 | 中 | 租賃 SaaS（JGB、Bananas）停在記錄與對帳；仲介集團有客源但沒有屋主入口 |
| 新進入者 | 高 | 仲介集團加掛代管容易；銀行與力興已在整合。平台的護城河只能是資料與持照網路 |
| 供應商（持照者、銀行） | 高 | 金流與信託只有銀行能做；查帳授權要銀行點頭 |
| 買方（屋主） | 高 | 付費意願未驗證；台灣客戶不習慣按年付費【低】 |
| 替代品 | 中 | 試算表與 LINE 免費；代管業者一條龍收 6% 至 10% |

含意：平台必須先綁定持照者與銀行，再對屋主收費。先做 B2B2C，再做 C 端。

## 8. 服務流程

### 8.1 Phase 1：從物件登錄到押金結算

| 步驟 | 誰做 | 平台做 | 錢在哪 |
|---|---|---|---|
| 經理人開通 | 經理人上傳證書與公司資料 | 商工 API 查公司，resim 人工核對證書，標章「證書資料已核對」 | 無 |
| 物件登錄 | 屋主或經理人 | 產權錨點（縣市＋區＋段＋建號含分號）、租賃單位 | 無 |
| 出租權源驗證 | 屋主上傳第二類謄本或授權書 | 比對登記名義人，記錄取得時間與到期 | 無 |
| 委託管理契約 | 屋主、代管業 | 專任管理人員簽章（§32 第 1 款） | 無 |
| 租賃契約 | 出租人、承租人；包租業時由專任管理人員簽章 | 既有三層文件與點點簽；依代管或包租分流簽章欄位 | 無 |
| 押金與租金 | 承租人直接匯出租人帳戶 | 鏡像帳、押金台帳、逾期提醒 | 出租人帳戶 |
| 修繕 | 屋主下單付款，經理人派工 | 工單與紀錄 | 屋主帳戶 |
| 退租點交 | 雙方，代管業簽點交證明 | 設備附件比對、照片、度數 | 無 |
| 押金結算 | 出租人 | 結算單雙方確認，退還證明簽章 | 出租人撥付 |
| 經理人更換 | 屋主、新舊經理人 | 移交包逐案確認 | 無 |

### 8.2 Phase 2：買賣七段加信託狀態

平台以僑馥七段流程為骨架（簽約前、簽約後、用印、完稅、過戶、點交、結案）。平台做三件事：每段的文件待辦與通知；接收建經或銀行的入帳狀態；把買賣方電子簽署的撥款指示交建經執行。查帳連結導向銀行或建經頁面，由買賣方本人驗證。平台比照特約地政士加入建經通路。

### 8.3 Phase 3：全資產清冊與繼承協調

平台做清冊、兩個期限提醒（遺產稅申報自死亡次日起 6 個月，繼承登記自死亡日起 6 個月）、文件保管、持照者協調。登記交地政士，申報交會計師，信託交銀行，法律文件交律師。建議只呈現中性事實：到期日、持有比例、文件缺漏。

## 12. 財務假設摘要

## 13. 新術語提案

`GLOSSARY.md` 沒有的概念，確認後再加入。

| 提案詞 | 定義 | 避免 |
|---|---|---|
| 經理人（Manager） | 受屋主委託執行寄售或代管的營業者的角色統稱；法定稱謂依業別顯示 | 物業、管家 |
| 執業主體（Practice Entity） | 持有許可或登記的公司或商號，契約當事人 | 業者 |
| 執業人員（Practitioner） | 持有證書的自然人，簽章人；受僱於執業主體 | 員工 |
| 組織（Organization） | 平台上的資料隔離單位 | 租戶、客戶 |
| 產權錨點（Property Anchor） | 縣市＋鄉鎮市區＋段小段＋建號（含分號）的唯一鍵 | 建物、房屋 |
| 租賃單位（Rental Unit） | 掛在錨點下的可出租單位，後綴 0000 代表整戶 | 房間、套房 |
| 出租權源（Leasing Authority） | 出租人出租該單位的依據：所有權、授權、轉租同意 | 權利 |
| 案件（Case） | 一個跨方流程的實例：一筆租賃、一筆買賣、一件繼承 | 交易、專案 |
| 信託案件識別碼（Trust Case ID） | 外部銀行或建經給的案件編號，平台只存識別碼與狀態 | 專戶 |
| 入帳確認（Deposit Confirmation） | 平台收到的「款項已入帳」事件，來源可為人工、對帳檔或推送 | 到帳通知 |
| 撥款指示（Disbursement Instruction） | 雙方電子簽署、交建經或銀行執行的付款指令 | 付款 |
| 鏡像帳（Mirror Ledger） | 平台記錄的款項分錄副本，真相在銀行 | 帳本 |
| 移交包（Handover Package） | 經理人更換時，每個租賃單位的六類資料集合 | 交接資料 |
| 資產清冊（Asset Inventory） | Phase 3 的全資產列表，標示來源與取得日期 | 資產證明 |

既有詞沿用：房東、租客、物件、合約、主約、補充合約、設備附件。「案件」在 GLOSSARY 的簽署任務 _Avoid_ 欄出現，加入時要寫明兩者的差別。

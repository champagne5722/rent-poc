# BRD：台灣不動產資產管理平台

日期：2026-10-29
狀態：提案草稿，待使用者審閱
依據：[調研報告](reports/台灣不動產資產管理平台調研.md)、[終稿稽核](audit/audit-final-report.md)
用詞：義務用「必須」，禁止用「不得」，許可用「得」，建議用「建議」。數字後的【高】【中】【低】沿用報告的信心標示。

## 1. 一頁摘要

平台的定位是「不動產資金與合約的流程層」。錢留在銀行信託專戶或房東帳戶，平台只管合約、文件、狀態與對帳。

第一個切入點是租賃端的包租代管業者與多戶房東。兆基事件後，主管機關研議押金專戶與租約接續。業者需要證明「租金與押金和自有資金分開」。目前沒有查到做這件事的軟體【低】。

第二個切入點是買賣端的履約保證流程。建經與銀行已有系統，平台以合作而非取代的方式進入。這是第二階段。

C 端媒合只做「自有房源上架」。不收成交佣金，不做帶看與議價。這避開經紀業許可。

三件事決定提案成敗，必須在開發前完成：

1. 向內政部、金管會、數位發展部書面函詢三個法律灰區。
2. 找到一家願意為租賃案件開信託專戶並提供入帳資訊的銀行。
3. 訪談 3 家包租代管業者，確認付費意願與政府補助上限。

## 2. 問題陳述

### 誰有什麼問題

| 客群 | 現況 | 痛點 | 證據 |
|---|---|---|---|
| 包租代管業者（約 10 萬至 11.6 萬戶）【中】 | 帳上混有自有資金、代收租金、應付租金、押金 | 無分帳義務，業者倒閉時房東與租客受損；主管機關正在研議押金專戶 | 兆基事件、內政部 2026-08-13 記者會【中】 |
| 多戶房東 | 用試算表或 LINE 管合約、收租、押金 | 押金返還沒有法定天數，糾紛集中在修繕、調漲、戶籍 | 內政部 109 年調查【中】 |
| 租客 | 只能靠自保，無法確認房東有權出租 | 詐騙損失 2025 年前 9 月逾 3,000 萬元【中】 | 刑事局【中】 |
| 建經與仲介（買賣） | 各家有自家系統，七段流程靠人工通知 | 專戶是否真的信託、款項進度不透明 | R1 筆記、2019 年安新案【低】 |
| 信託銀行（受託人） | 2026-09 法務部書函要求受託人保有管理處分權限 | 委託人自行出租時，受託人需要出租與租金紀錄 | 法務部書函【高】 |

### 不解決會怎樣

包租代管戶數目標 2032 年 25 萬戶【高】。沒有分帳工具，每一次業者倒閉都會重演兆基事件。房東回到試算表，租客回到自保。政策若強制押金專戶，業者會臨時找工具，市場會被先到的人拿走。

## 3. 商業模式

### 3.1 價值主張

| 對象 | 一句話 |
|---|---|
| 包租代管業者 | 用銀行專戶和平台對帳，向房東與主管機關證明錢沒混用 |
| 多戶房東 | 合約、押金、收租、修繕一個地方管，退租時押金算得清楚 |
| 租客 | 簽約前確認房東有權出租，押金進專戶而不是房東口袋 |
| 建經與仲介 | 七段流程的狀態與文件自動通知各方，不用人工追 |
| 信託銀行 | 受託財產的出租與租金紀錄可查，符合法務部對消極信託的要求 |

### 3.2 平台做什麼、不做什麼

| 平台做 | 平台不做 | 原因 |
|---|---|---|
| 合約、文件、狀態、對帳、通知 | 持有任何一方的款項 | 信託業法 §33、電支條例、洗錢防制法 §6【高】 |
| 蒐集雙方電子簽署的撥款指示，交銀行執行 | 自己轉帳或撥款 | 同上 |
| 自有房源上架、物件驗證 | 帶看、議價、代簽、挑房客、依成交計酬 | 經紀條例 §4、§32【高】 |
| 房東自己操作的記帳、提醒、對帳、報表 | 平台人員代房東催收、保管押金、協調糾紛 | 租賃條例 §3、§36【高】；灰區二待函詢 |
| 與持照代管業合作，承接代管功能 | 自己登記為代管業 | 第一階段不領牌照 |

### 3.3 收入模式

收入順序依國外標竿排序：附加服務高於訂閱，訂閱高於廣告【高】。但台灣的金流附加服務需要牌照，第一階段只能做訂閱與案件費。

| 收入來源 | 向誰收 | 計價單位 | 階段 | 法規前提 |
|---|---|---|---|---|
| 租賃管理訂閱 | 代管業者、多戶房東 | 每租賃單位每月 | Now | 無 |
| 電子簽約與文件費 | 代管業者、房東、建經 | 每份合約 | Now | 無 |
| 物件驗證與謄本歸檔 | 房東、代管業者 | 每物件每次 | Now | 使用者自行上傳謄本 |
| 信託專戶案件費 | 代管業者、建經 | 每案件 | Next | 銀行合作契約 |
| 買賣流程層案件費 | 建經、仲介 | 每案件 | Later | 建經合作契約 |
| 導流分潤：保險、搬家、清潔 | 合作商 | 每成交 | Later | 保險分潤需保險代理或經紀資格 |
| 自有房源上架 | 房東 | 每筆固定費 | Next | 不得依成交計酬 |

定價假設，全部待驗證：

| 項目 | 假設 | 參考 | 信心 |
|---|---|---|---|
| 租賃管理訂閱 | 每單位每月 30 至 80 元 | 好未來每間每月 10 元【低】；AppFolio 每單位每月 1.49 美元【高】；Bananas 收月租 6%【低】 | 低 |
| 電子簽約 | 每份 100 至 300 元 | 點點簽成本加流程價值 | 低 |
| 信託專戶案件費 | 每案件 500 至 2,000 元 | 價金信託簽約費約 1,000 元【中】 | 低 |

### 3.4 單位經濟試算

假設一家代管業者 1,000 戶，每戶每月 50 元，年收 60 萬元。全台 11.6 萬戶若滲透 10%，年收約 700 萬元。這個數字只能說明「訂閱費撐不起公司」。案件費與買賣端是必要的第二、第三收入。

社宅代管的代管費由政府撥付，房東免付報酬【高】。業者對軟體的付費上限等於政府補助減營運成本。補助金額表沒有取得，這是最大的商模缺口。

| 玩家 | 關係 | 理由 |
|---|---|---|
| 591 | 不競爭流量 | 591 市占逾八成【低】，純刊登無勝算 |

| 銀行信託部 | 合作 | 銀行是受託人，平台是流程與對帳層 |

## 4. 服務流程

### 4.1 租賃：從上架到退租

```
物件登錄 ──► 出租權源驗證 ──► 合約簽署 ──► 押金入專戶 ──► 收租對帳 ──► 退租點交 ──► 押金結算
   │              │               │              │              │             │             │
 建號錨點     謄本或授權書     點點簽三層文件   銀行虛擬帳號     鏡像帳       設備附件比對    雙方確認後
 單位 ID      權源鏈條         設備附件快照     入帳確認事件     報表         照片與度數      指示銀行撥款
```

| 步驟 | 誰做 | 平台做 | 錢在哪 |
|---|---|---|---|
| 物件登錄 | 房東或代管業者 | 以建號複合鍵建立產權錨點，分租單位掛在錨點下 | 無 |
| 出租權源驗證 | 房東上傳第二類謄本或授權書 | 比對登記名義人，記錄取得時間，到期提醒 | 無 |
| 合約簽署 | 房東、租客 | 沿用 rent-poc 三層文件與點點簽 | 無 |
| 押金入專戶 | 租客匯款 | 產生虛擬帳號，接收入帳確認事件 | 銀行信託專戶，或房東帳戶 |
| 收租對帳 | 租客匯款 | 鏡像帳記錄，逾期提醒給房東 | 房東帳戶 |
| 退租點交 | 房東、租客 | 設備附件比對，照片與度數存證 | 無 |
| 押金結算 | 雙方確認 | 蒐集雙方電子簽署的撥款指示，交銀行執行 | 銀行撥付 |

Now 階段沒有銀行合作時，押金進房東帳戶。平台只記鏡像帳。這仍能證明「代管業者沒經手押金」。

### 4.2 代管業者更換：移交包

寄居蟹案顯示轉銜是逐案處理【中】。平台把每個租賃單位的資料打包成移交包：

1. 權屬：產權錨點、謄本、授權書。
2. 人：房東、現任租客、租約。
3. 屋況：現況確認書、設備附件、照片。
4. 錢：押金台帳、預收租金、欠費、代收代付清單。
5. 實物：鑰匙與門禁卡清冊。
6. 行政：修繕紀錄、管委會窗口。

新業者接手時，逐案由房東確認，平台產生新委託契約。

### 4.3 買賣：七段流程層（Later）

平台以僑馥七段流程為骨架，角色為買方、賣方、仲介、地政士、建經、銀行。平台做三件事：

1. 每段的文件清單與待辦，通知當前負責角色。
2. 入帳確認事件來自建經或銀行，平台更新案件狀態。
3. 撥款指示由買賣雙方電子簽署，交建經或銀行執行。

這一段依賴建經或銀行願意推送入帳狀態。沒有公開規格【低】，只能商務洽談。

## 7. 最高風險假設與驗證方式

依 product-brainstorming 的假設測試，先找「錯了就整個提案作廢」的假設。

| 假設 | 錯了會怎樣 | 最便宜的驗證 | 時程 |
|---|---|---|---|
| A1 代管業者願意為分帳證明付費 | 第一階段沒有客戶 | 訪談 3 家，問「每戶每月付多少」與「補助剩多少」 | 2 週 |
| A2 至少一家銀行願意開租賃信託專戶 | Next 階段無法啟動，只能做記帳軟體 | 帶金流圖拜訪 2 家銀行信託部 | 4 週 |
| A3 平台對帳與提醒不構成代管 | 必須登記代管業或全部透過合作業者 | 函詢國土署，附功能清單 | 4 至 8 週 |
| A4 房東能提供謄本或授權書 | 物件錨點只剩門牌，唯一性變弱 | 在 rent-poc 加謄本上傳，觀察 20 位房東的完成率 | 4 週 |
| A5 主管機關會推動押金專戶 | 賣點變弱，但分帳對房東仍有價值 | 追蹤內政部公告；不依賴 | 持續 |

A1 與 A2 可以平行。A3 函詢期間先做房東自操作的功能。

| 產權錨點（Property Anchor） | 以「縣市＋鄉鎮市區＋段小段＋建號（含分號）」為唯一鍵的產權單位 | 建物、房屋 |
| 租賃單位（Rental Unit） | 掛在產權錨點下的可出租單位，後綴 0000 代表整戶 | 房間、套房 |
| 出租權源（Leasing Authority） | 出租人出租該單位的依據：所有權、授權、轉租同意 | 權利 |
| 案件（Case） | 一個跨方流程的實例：一筆租賃或一筆買賣 | 交易、專案 |
| 信託專戶（Trust Account） | 銀行以受託人身分開立的案件專屬帳戶 | 履保專戶、託管帳戶 |
| 入帳確認（Deposit Confirmation） | 平台收到的「款項已入專戶」事件，來源可為人工、對帳檔或銀行推送 | 到帳通知 |
| 撥款指示（Disbursement Instruction） | 雙方電子簽署、交銀行執行的付款指令 | 付款、轉帳 |
| 鏡像帳（Mirror Ledger） | 平台記錄的銀行專戶分錄副本，真相在銀行 | 帳本、金流 |
| 組織（Organization） | 平台上的資料隔離單位：一家代管業者、一位多戶房東、一家銀行各為一個組織 | 組織（易與租客混淆）、客戶 |
| 代管業者（Property Manager） | 依租賃條例登記的租賃住宅代管業 | 物業公司、管理公司 |
| 移交包（Handover Package） | 代管業者更換時，每個租賃單位的六類資料集合 | 交接資料 |

既有詞沿用：房東、租客、物件、合約、主約、補充合約、設備附件。「物件」在新架構中等同一個租賃單位。

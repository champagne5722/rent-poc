# F 線交接：屋主資產總覽 v1 與移交包

先讀 `README.md`。spec 是 MIL-94，決議在 ADR-0024。它是六條線裡唯一能在 A 線之前開始做畫面的，資料接線等 B、C、E 線。

## 範圍與依據

- P0-20 屋主資產總覽 v1、P0-22 移交包。
- prototype：分支 `prototype/mil-47-owner-overview`（commit `761a1105`），保留不合併。截圖與欄位清單在 Linear MIL-47 的留言。定案：總覽用「先看需要注意，再列全部租賃單位」的版本；月報表（屬 E 線）用摘要加分段明細。欄位全部標「待訪談驗證」。
- 決議（MIL-47）：逾期是累計未足額，已入帳依配置；每列一個帳務更新日，頁首「資料截至」與「金額以銀行紀錄為準」，不在每個數字旁標時間（P0-20 規則 2 改寫，待改項目在 MIL-61）；押金持有人在每列，只有逾約定日數才進需要注意清單；頁首的出租中是 `active` 加 `move_out`。
- MIL-47 給 spec 的兩個發現：沒有案件的空置單位照 P0-20 的資料來源會漏列；現有 `AppShell` 不支援 375px，對代管案件的屋主顯示「建立合約」，屋主端需要自己的殼層。
- 移交包：ADR-0014 與 0015 定了跨組織移交的分錄做法（兩個組織各寫一筆，業務事件 ID 都是移交包 ID，中間狀態要顯示完成與否）；ADR-0016 定了移交生效時舊案件轉 `terminated`、有進行中簽署任務時擋下；ADR-0013 定了租賃單位 ID 跨組織不變；P0-22 規則 3 只做快照雜湊，不做 hash chain。
- 移交包匯入是 P1-01，不做。

## 依賴

- 總覽讀的資料來自 B（租賃單位）、C（案件成員與組織）、E（應收、押金、修繕）。畫面能先用假資料做，接線的票分別 blocked-by 各線的對應票。
- 移交包依賴 C（組織與案件）、E（押金分錄）。
- 整合分支 `integration/line-f` 從 main 分出。畫面票可以直接做；接線票等對應線的票併進各自的整合分支。
- 屋主端殼層若由 F 線做，C 線的介面換字與殼層題目要對齊，規格階段先在 Linear 的 MIL-64 或 C 線 spec 留言協調。

## 規格要涵蓋的題目

屋主端殼層（與 C 線分工）；總覽的資料來源與每個欄位對應的表或函式；需要注意清單的規則；空置單位的來源；批次查簽署進度避免每列各查；手機寬度；移交包的內容清單、快照、產出與接收流程、生效日、舊案件終止、跨組織分錄的兩個交易；移交包的畫面；測試 seam（純函式：需要注意規則、列的推導；畫面手動冒煙）。

## 第一步

1. 開一個 Opus 子對話寫規格，流程見 README 第 3 節。prototype 分支是起點，規格要引用 MIL-47 的欄位清單。
2. spec 發 Linear 時 related MIL-35、MIL-47。畫面票不設 blocked-by，接線票 blocked-by 對應線的票。
3. 畫面票能立刻派實作，載入 impeccable。

## 現況（spec 發佈後）

- spec：MIL-94。ADR-0024 跨組織移交以後繼案件承接、協調列放 `control.handovers`。ADR-0016 決議 10 加註由 ADR-0024 修正。GLOSSARY 新增需要注意清單、帳務更新日、後繼案件。以上在分支 `line-f-spec`。
- ADR 編號：E 線的分支已用 0022、0023，F 線取 0024。併 main 前再確認一次。
- 票：畫面票 MIL-95 到 MIL-98，用假資料或記憶體 adapter，能立刻派。接線票 MIL-99、MIL-101、MIL-102、MIL-105、MIL-107、MIL-110。票號對照在 MIL-94 的留言。
- 待補關聯：接線票描述最上方寫了 B、C、E 線待補。各線 spec 發佈後，照 MIL-94 Further Notes 的「待補的跨線關聯」表補 blocked-by。
- 待知會：A 線要在 `control` 的權限規則與 CI 清單放行 `control.handovers`。C 線要提供 `currentOwnerSession()` 與 spec 列的介面。E 線的 `ledger` 模組要接受 F 線加 `recordHandoverRelease`、`recordHandoverReceipt`。

# E 線交接：鏡像帳、押金台帳、逾期提醒、修繕、點交、結算、月報表、承租人端

先讀 `README.md`。這條線還沒有 spec，第一步是寫規格。它有 8 條 P0，地圖的 Not yet specified 寫「可能要再拆」，規格階段先決定是否拆成兩條。

## 範圍與依據

- P0-13 鏡像帳與入帳確認、P0-14 押金台帳、P0-15 逾期提醒、P0-16 修繕紀錄、P0-17 點交紀錄、P0-18 押金結算單與退還證明、P0-19 屋主月報表、P0-21 承租人端查閱。
- ADR：0014（不持有款項、入帳確認轉接層、兩種來源 `manual` 與 `statement_file`、兩層 inbox、跨來源重複進待配對清單、收款帳戶表取代 custody、現金收款、撥款指示不建表、押金帳戶規則表在 `control`）、0015（雙式分錄、應收不進鏡像帳、押金台帳不存餘額、沖銷規則、資料庫約束觸發器、應收期別與配置、結算單送簽後餘額變動必須撤回重出）、0016（案件不訂閱入帳、點交證明與結算單與退還證明是獨立簽署標的）、0018（這三種文件的簽署序列）。
- 決議：MIL-42 的 Q1 逾期提醒只手動按鈕；Q3 押金帳戶社宅阻擋、一般代管警告並記錄確認者、通知委託人、警告文字不寫合法或違法、代收押金交付追蹤（約定日數與實際交付日，逾期在月報標示）。MIL-47 的月報表欄位定案（摘要加分段明細、單位是屋主乘產出組織乘月份、逾期累計未足額、已入帳依配置、代收代付差額加說明欄、報表註明金額以銀行紀錄為準）。
- MIL-35 留言：GLOSSARY 缺「社宅代管案件」已由 MIL-44 補；社宅屬性由誰標記、標錯如何處理尚未決定，E 線 spec 必須定。
- 點點簽撤回能力已確認（`voidSignTask` 現有程式碼在用）。

## 依賴

- 鏡像帳的分錄不可改靠 PostgreSQL 觸發器，依賴 A 線。E 線 tickets 的第一張 blocked-by A 線的 MIL-83（合約與合約歷程走 PostgreSQL）。
- 整合分支 `integration/line-e` 從 `integration/line-a` 分出。
- 承租人端的登入依賴 C 線；逾期提醒的 worker 依賴 A 線的 ADR-0020。規格要寫清楚邊界。
- 押金結算單等三種文件的簽署走簽署模組，D 線的規則表已含它們的序列。

## 規格要涵蓋的題目

是否拆成兩條（帳務與文件、承租人端）；入帳確認的兩種來源與畫面；對帳檔的 CSV 欄位對應；待配對清單；收款帳戶登錄與持有人；押金台帳、扣抵、異議；沖銷；應收期別與配置、預收、一期多付；逾期提醒的手動按鈕與逾期標示；修繕紀錄；點交紀錄與點交證明簽署；押金結算單與退還證明；月報表的產出與匯出；承租人端能看什麼；社宅屬性標記；押金帳戶規則表的 migration 與確認紀錄；測試 seam（純函式：規則評估、期別狀態、分錄平衡性質測試；整合：PGlite 配 SET ROLE）。

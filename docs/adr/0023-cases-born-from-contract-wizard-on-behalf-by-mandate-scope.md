# 案件從建約流程長出，代操作以委託範圍授權

ADR-0016 定了案件的狀態與成員，但沒有寫案件從哪裡來。現有系統只有物件與合約，D 線又把分流條件暫存在合約上（ADR-0021）。決議：建約 wizard 第一步改為建立租賃案件，合約掛在案件下，分流條件改由案件提供。既有合約遷移時，每份合約建一個自管租賃案件。權限只經 `authorize()`，代操作動作另查委託範圍。

本決議延伸 ADR-0016、ADR-0018、ADR-0021，並結束 ADR-0021 決議 1、3、4 的過渡。

## 決議內容

1. **租賃案件的建立。** 建約 wizard 第一步改為「建立租賃案件」：選物件、業務類型，以及是否有經紀業者居間。案件建成 `draft`，合約掛在案件下。

   | 主辦組織 | 允許的業務類型 | 建立前的檢查 |
   |---|---|---|
   | 屋主組織 | 自管 | 無 |
   | 執業主體組織 | 代管、包租 | 對應業別是 `verified`（P0-02 AC4），且至少一位可簽章的專任管理人員（P0-05 規則 4、§25） |

   - 代管的租賃案件必須連到有效的委託管理案件，見決議 4。
   - 屋主出租給包租業者的合約，由包租業者主辦，業務類型是自管（ADR-0018 決議 8）。
   - 撤回或拒簽後複製的新草稿留在同一案件（ADR-0006、ADR-0016 決議 12）。

2. **分流條件改由案件提供。** 業務類型與「是否有經紀業者居間」存在案件。承租人是否為包租業者，由承租人成員的 party 是否為包租業別的執業主體推導。

   - 新合約送簽時，`routeSignatures()` 的輸入取自案件。
   - D 線存在合約欄位的快照保留給既有合約，不回寫（ADR-0021 決議 1）。

3. **既有合約的遷移。** 每份既有合約建一個自管租賃案件，掛在同一組織，`current_contract_id` 指向該合約。

   | 合約狀態 | 案件狀態 | 說明 |
   |---|---|---|
   | 草稿 | `draft` | |
   | 待乙方簽、待甲方簽、待執業人員簽 | `signing` | |
   | 已完成 | `active` | 退租與結案由使用者之後操作 |
   | 已拒簽 | `draft` | 合約本身維持「已拒簽」，案件回到可重新擬約的狀態（ADR-0016 決議 3） |
   | 已撤回 | `draft` | 合約本身維持「已撤回」，同上 |

   - 衍生關聯（`derived_from`）連在一起的合約歸同一案件，`current_contract_id` 指向最新一份。
   - 承租人成員依合約乙方的 email 建立，見決議 5。
   - 遷移寫一筆 `migrated` 案件事件，不補寫歷史轉移。

4. **委託管理案件與租賃案件的連結。** 委託管理合約全員完成時，委託管理案件轉 `active`。上傳紙本契約書時，案件由 `draft` 直接進 `active`（ADR-0016 決議 9）。

   - 受託人建立代管的租賃案件時，系統必須連到有效的委託管理案件。該案件必須涵蓋這個租賃單位，沒有就擋下（P0-09 AC3）。
   - 委託管理合約完成時，系統自動連結既有的代管租賃案件（P0-11 AC3）。條件是案件屬於受託人組織、未結案，且租賃單位在委託標的清單上。
   - 委託管理案件轉 `terminated` 或 `expired` 時，系統關閉受託人在連結案件的成員 `valid_period`，並通知屋主移交（P0-11 AC5、P0-22）。
   - 移交生效時的系統轉移依 ADR-0024：舊委託管理案件轉 `terminated`，舊租賃案件轉 `closed` 並寫 `handed_over` 事件，接收方建立後繼案件。本 ADR 不重複定義，C 線的案件模組提供這些轉移的入口。
   - 委託管理案件的屋主是 `mandator` 成員。連結的代管租賃案件中，屋主是 `lessor` 成員，所以不必加入受託人組織（P0-09 AC2）。

5. **案件成員的產生。**

   | 關係 | 何時加入 | 由誰 |
   |---|---|---|
   | `lessor` | 建立案件時。代管案件是屋主，包租案件是包租業者 | 系統 |
   | `lessee` | 送簽時，依合約乙方 email 找或建 party | 系統 |
   | `co_lessee` | 主辦組織手動加入 | 主辦組織 `admin`、`staff` |
   | `mandator`、`mandatary` | 建立委託管理案件時 | 系統 |
   | `owner` | 包租案件建立時，取自包租業者與屋主的自管案件 | 系統 |
   | `practitioner` | wizard 指派簽章人時 | 主辦組織 |
   | `broker` | 主辦組織勾選居間並選經紀業者時 | 主辦組織 |

   - 承租人換 email 時，由出租人或受託人更新成員 email。舊 email 立即失效，寫稽核紀錄（P0-21 AC5）。
   - 經紀業者組織只得讀合約。第一版不做經紀業者自己指派經紀人，經紀人由主辦組織從全域登錄選取。

6. **`authorize()` 是唯一的權限入口。** `authorize(t, action, object)` 拒絕時丟 `Forbidden`。對外，拒絕與資料不存在是同一個回應（P0-02 AC1）。

   - 內部分成兩段：載入事實，再呼叫純函式 `decideAccess(facts, action)`。
   - 動作是程式內的常數表。每列寫允許的組織角色、允許的案件關係、允許的案件狀態，以及是否為代操作動作。
   - `withCaseMemberTx` 的第 2 步呼叫同一個 `authorize()`（ADR-0016 決議 16）。
   - 結案後的唯讀由案件狀態判斷，不結束 `valid_period`（ADR-0016 決議 15）。
   - 之後改用 OpenFGA 或 SpiceDB 時，只換 `authorize()` 的實作（架構 4.5）。

7. **代操作動作查委託範圍。** 代管租賃案件中，受託人的代操作動作必須全部符合下列條件（P0-11 AC4、P0-09 AC4）。

   1. 連結的委託管理案件是 `active`。
   2. 該租賃單位在委託標的清單上。
   3. 該列的委託範圍含這個動作。
   4. 受託人的代管業別是 `verified`，且至少一位可簽章的專任管理人員。

   | 委託範圍 | 代操作動作 |
   |---|---|
   | 收租 | 登錄入帳確認、逾期提醒 |
   | 押金管理 | 登錄押金分錄 |
   | 修繕 | 建立與處理修繕紀錄 |
   | 點交 | 確認點交、發起退租 |

   委託範圍的查詢函式由 D 線提供（ADR-0021 決議 8）。E 線的動作在加入動作表時標示是否為代操作。

8. **接手 `practiceRegistry`。** C 線提供真實 adapter，經 `registry` 的定義者函式查詢，回傳形狀不變。

   - 查執業主體：依業別。
   - 查當事人簽署人候選：執業主體組織的成員（ADR-0018 決議 2）。
   - 查執業人員候選：依證書種類與專任要求，只回傳在查詢時點可簽章的人。
   - 查可簽章的判定事實：業別、證書、任職的狀態，`valid_until`，任職期間，三層最新的核對紀錄 ID。
   - 回傳不得透露別的組織（ADR-0012 決議 8）。
   - seed adapter 保留給測試。正式環境未設定時擋下送簽的規則不變。

9. **過渡結束。** `checkSendPreconditions()` 第 2 項改回 ADR-0018 決議 10 的原文：規則要求執業人員時，案件有指派 `practitioner` 成員。D 線合約上的指派搬成案件成員。這結束 ADR-0021 決議 4 的過渡。

## Considered Options

- **案件與合約分開建立：** 使用者先建案件再建約，案件的意義較清楚。代價是多一個步驟，使用者要重新學習。
- **既有合約不建案件：** 遷移最省事。但清單與權限要同時處理有案件與沒有案件的合約。
- **拒簽與撤回的合約遷移成 `aborted` 案件：** 與合約狀態一致。但 ADR-0016 規定撤回與拒簽回到 `draft`，使用者也會想在同一案件重新擬約。
- **委託管理合約完成時自動建租賃案件：** 清單上每個租賃單位一個案件，受託人不用自己建。但空置單位會多出沒有承租人的案件。
- **權限寫在每個 route：** 不用設計動作表，但無法做全矩陣測試，之後也無法換成 ReBAC。
- **經紀業者自己指派經紀人：** 符合 ADR-0016 決議 14 的描述，但要另一條跨組織寫入路徑，P0 沒有對應的 AC。

## Consequences

- 建約 wizard 的第一步改變。既有的建約測試要改寫。
- 每次建立代管或包租案件都要查業別與專任管理人員，結果不快取。
- 包租案件的 `owner` 成員依賴屋主與包租業者的自管案件存在。沒有這個案件時，包租案件沒有 `owner` 成員，屋主在資產總覽看不到該轉租案件。
- 經紀業者在 Phase 1 不能自己指派經紀人，也不能開案件。
- 動作表是 E 線加動作時必須修改的地方。
- 架構文件第 3.12 節與第 4.5 節的待改項目由 MIL-61 處理。

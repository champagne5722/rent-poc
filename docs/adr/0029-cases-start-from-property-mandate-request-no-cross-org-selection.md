# 案件從物件往下建立，委託從屋主的委託申請開始，第一階段不做跨公司選人

ADR-0023 讓案件從建約 wizard 長出，主辦組織也能從全域登錄選別家公司的人員。現況是業者登錄屋主的房子後直接送委託管理合約。使用者 2026-11-10 指出兩個問題。第一，屋主會突然收到不認識的業者寄來的簽約信。第二，業者同時被「物件合規」與「委任身分合規」兩件事擋住。決議：案件一律從物件往下建立。業者不得主動寄任何東西給還沒建立關係的屋主，委託從屋主送出委託申請開始。第一階段不做跨公司選人。

本決議修訂 ADR-0023 決議 1、5、8 與 ADR-0025 決議 13。對照表在「修訂的舊決議」。法律假設待法務確認，集中在 MIL-62。調研筆記是 Q30 與 Q32。

## 決議內容

1. **案件從物件往下建立。** 建立租賃案件與委託管理案件的入口，都在物件與它的租賃單位上。

   - 建約 wizard 不再有「選物件」這一步。物件由入口帶入。
   - 合約列表與工作台若保留「新增」按鈕，按鈕只能帶使用者到物件列表。
   - 物件沒有通過文件核對時，入口不出現（ADR-0028 決議 5）。

2. **誰看得到物件。** 看得到一個物件的，只有它的持有者與受委託管理它的人。能在這個物件上建立案件的，也只有這些人。

   | 身分 | 怎麼取得 |
   |---|---|
   | 持有者 | 自己登錄物件，並通過文件核對 |
   | 受委託管理的人 | 接受屋主的委託申請（決議 6），或走屋主不上線的流程並通過核對（決議 7） |

3. **第一階段不做跨公司選人。** 合約上的簽章人與當事人簽署人，都由主辦組織從自家指派。任何組織都看不到別的組織的人員。

   - 居間只支援主辦組織自己兼營經紀業。主辦組織有已驗證的經紀業別時，才得勾選居間，並指派自家的經紀人。
   - 屋主端不顯示居間選項。
   - 外部經紀公司居間的合約，第一階段不能在平台上簽。
   - 移交不受影響（ADR-0024）。

4. **委託管理合約只由代管業者擬約與送簽。** 屋主是簽署人與案件成員。屋主端不得建立委託管理合約。現況的屋主端草稿與選受託人的畫面，必須移到業者端。

5. **業者不主動聯絡屋主。** 關係成立之前，業者不得經平台寄任何東西給屋主。簽約信與不帶合約的邀請信都不行。屋主自己登入之前，平台不寄任何東西給屋主。

6. **委託申請：屋主會上線時。**

   1. 業者在線下把自己的連結或 QR code 交給屋主。業者得先代填房子的資料。
   2. 屋主點連結，用 email 驗證碼登入。屋主看到業者的名稱、統編與已驗證的業別。
   3. 屋主確認要交給這家業者的租賃單位，並送出委託申請。謄本由屋主上傳，或由業者代傳。
   4. 業者收到通知。業者接受委託申請，並指派管理人員。
   5. 業者從物件建立委託管理案件，擬委託管理合約並送簽。
   6. 委託管理合約完成後，業者從租賃單位建立租賃案件。

   - 業者代填的資料在屋主確認之前不算登錄。它不佔建號，別人也查不到。
   - 委託申請送出後，業者 7 天內沒有接受時，申請失效。
   - 業者接受委託申請，而且物件通過文件核對之後，業者才看得到這些物件。
   - 帶有代填資料的連結 7 天有效。逾期後代填的資料作廢。
   - 業者接受之前，屋主得收回委託申請。
   - 業者得不接受委託申請。屋主只看到「未接受」，畫面不顯示原因。
   - 合約完成之前，屋主與業者都得結束已接受的委託申請。結束後業者看不到這些物件。
   - 業者接受後 30 天內沒有送出合約時，委託申請失效。

7. **屋主不上線時。** 業者自己登錄物件，上傳紙本的委託管理契約與謄本。平台營運者核對通過後，委任生效。業者以受委託人的身分看得到這個物件。屋主不收到任何信。

8. **包租用同一條流程。** 屋主把房子租給包租業者時，同樣由屋主從業者給的連結送出委託申請。業者接受後，從物件建立屋主與包租業者之間的租賃案件。

9. **一個租賃單位同一時間只交給一家業者。** 租賃單位有進行中的委託申請或有效的委託時，屋主不得再對另一家業者送出委託申請。

   - 屋主必須先結束前一筆：收回委託申請，或走換業者的移交（ADR-0024）。
   - 同一位屋主的其他租賃單位，得交給別家業者。
   - 這項檢查只用屋主自己的資料，不違反 ADR-0028 決議 1。

## 修訂的舊決議

| 舊決議 | 修訂後 |
|---|---|
| ADR-0023 決議 1 | 建約 wizard 第一步不再建立案件並選物件。入口改在物件（決議 1）。主辦組織與業務類型的規則不變 |
| ADR-0023 決議 5 | `practitioner` 與 `broker` 成員只得是主辦組織自家的人。「經紀人由主辦組織從全域登錄選取」取消 |
| ADR-0023 決議 8 | 當事人簽署人與執業人員的候選，只回主辦組織自己的成員。跨組織的候選查詢取消 |
| ADR-0025 決議 13 | 跨組織取得同一個租賃單位的途徑，加上已接受的委託申請。受託的業者得在受託的物件下新增租賃單位 |
| PRD P0-10 的居間合約 | 只限主辦組織自己兼營經紀業 |
| PRD P0-11 AC1 | 建立委託管理合約的前提，加上已接受的委託申請，或決議 7 的核對通過 |

## Considered Options

- **業者先送委託管理合約，屋主簽了就當成確認：** 步驟最少。但已驗證的代管業者能對任何 email 寄簽約信。使用者：「基本上一定會覺得是資安問題」。
- **業者寄不帶合約的邀請信（Q32 方案二）：** 屋主不用自己找連結。但這仍是陌生業者主動寄信給屋主。
- **維持現況，業者登錄建號，重複時送審核，再擬約：** 不用做新功能。但業者被物件與委任兩件事擋住，業者登錄屋主的房子也會製造重複。
- **對方公司確認並指派人員（Q30 方案 A）：** 符合「由業者指派」的法條文字，也支援外部經紀公司。但要做公司名錄、邀請與等待。第一階段沒有非做不可的情境，之後要做時從這個方案開始。
- **屋主產生邀請碼，線下交給業者輸入（Q32 方案三）：** 業者沒有任何入口能打擾屋主。但屋主要先有帳號並找到按鈕。第一階段不做，業者的連結與 QR code 已涵蓋。
- **建約 wizard 第一步只能選已通過核對的物件：** 改動最小。但使用者否決：起點是物件，看得到物件的人才能建立案件。

## Consequences

- 建約的入口改變。合約列表與工作台的「新增合約」要改成帶到物件列表。這屬於 UI 重構線的建約精靈與物件頁。
- 委託申請是新的資料與狀態。它不是案件，也不是合約。業者接受之後才有委託管理案件。
- 屋主會上線時，物件登錄在屋主名下。屋主第一次從連結登入時，系統替屋主建立屋主的組織。
- 屋主會上線時，所有權的出租權源節點在屋主的組織。受託人經委託申請讀到核對的結果，不另存一份謄本。
- 屋主不熟電腦時，委託申請多了登入與確認的步驟。屋主不上線的流程是退路。
- 屋主不上線的流程沒有屋主的線上確認。保護來自平台營運者核對紙本契約與謄本。屋主之後自己登錄同一個物件時，依 ADR-0028 決議 4 處理。
- 跨組織的候選查詢移除後，`practiceRegistry` 的 `selecting` 關係移除，`bound` 只看案件成員。
- 「委託申請」是否也用在包租，還沒有定。包租在法律上是租賃，不是委任。使用者要求用詞符合法律，調研筆記是 Q33。
- 委託管理定型化契約規定審閱期至少三日，不得拋棄。送簽時怎麼滿足，待法務確認。
- 決議 6 的期限與決議 9 由使用者 2026-11-10 確認。
- 委託申請不用「撤回」這個詞。「撤回」在術語表專指中止簽署任務。
- 延後三個項目。第一個是屋主在平台上找代管業者的名錄與媒合。第二個是外部經紀公司居間。第三個是屋主看業者標示為可見的備註。
- MIL-116、MIL-77、MIL-119 的範圍要依本決議改寫。

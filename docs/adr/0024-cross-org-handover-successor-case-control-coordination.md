# 跨組織移交以後繼案件承接，協調列放 `control`

P0-22 的移交包把代管租賃案件交給新受託人，或交回屋主自管。每個執業主體是一個組織，屋主也有自己的組織，所以每次移交都跨組織。ADR-0016 決議 10 寫「移交不改租賃案件的狀態，只改業務類型或委託連結」，這只在同一組織內成立。ADR-0015 決議 9 已定跨組織分錄寫兩筆、兩個交易。決議：接收方組織建立後繼案件，沿用同一個租賃單位 ID。舊租賃案件在生效時轉 `closed`。兩個組織之間的協調列放 `control`，快照內容各自存在兩側組織。

## 決議內容

1. **適用範圍。** 移交只適用代管租賃案件與它連結的委託管理案件（P0-09 發起移交欄）。自管與包租不適用。委託標的清單上沒有租賃案件的租賃單位也產生移交包，但沒有分錄，也沒有後繼案件。

2. **後繼案件。** 接收方組織建立一個新的租賃案件，租賃單位 ID 與舊案件相同（ADR-0013 決議 9）。接收方是新受託人的組織，改自管時是屋主組織。後繼案件的業務類型是代管或自管。後繼案件記錄移交包 ID，不建跨組織外鍵。

3. **舊租賃案件轉 `closed`。** 生效時，系統把舊租賃案件轉 `closed`，寫 `handed_over` 案件事件。未結原因由系統填入移交包 ID（ADR-0016 決議 6）。不新增第八個狀態，因為 `closed` 已經表達「這個組織不再處理這個案件」。舊委託管理案件轉 `terminated`，舊受託人的 `valid_period` 關閉（ADR-0016 決議 9、15）。

4. **後繼案件不建合約列。** 租期與租金條件存在案件欄位（ADR-0016 決議 15）。已簽 PDF 與合約欄位快照放在移交包內，附 SHA-256。續約與改約照 ADR-0016 決議 8、12 開新案件。複製合約列會與 ADR-0006 的不可變與衍生規則衝突，所以不採用。

5. **協調列放 `control.handovers`。** 協調列存移交包 ID、租賃單位 ID、交出組織、接收組織、狀態、生效日、快照雜湊、兩側是否完成。協調列不存個資與金額。讀寫只經固定函式，函式先檢查呼叫者是屋主、交出方或接收方的成員。表由 F 線以 migration 建立，A 線在 `control` 的權限規則與 CI 清單放行。

6. **快照存在兩側組織。** 快照內容是六類索引、缺項、帳務快照與已簽 PDF 的雜湊。交出側在生效時寫入，接收側在接手完成時寫入同一份位元組。舊受託人保留唯讀副本（P0-22 規則 5）。保存期限待法務確認（Q16，MIL-62）。

7. **雜湊。** 快照以鍵排序的 canonical JSON 計算 SHA-256。系統存下原始位元組，驗證時重算，原則同 ADR-0019。只做快照雜湊，不做 hash chain（ADR-0015 決議 9）。

8. **狀態。** `draft`、`owner_confirmed`、`accepted`、`released`、`completed`、`cancelled`。`released` 表示交出側的交易已提交。`released` 之後不得取消，只能重試接收側。畫面必須顯示兩側各自是否完成。

9. **分錄。** 每側一筆分錄，業務事件 ID 都是移交包 ID。

   | 側 | 事件 | 借方 | 貸方 |
   |---|---|---|---|
   | 交出 | `handover_released` | `liability.deposit.{舊案件}`、`liability.prepaid_rent.{舊案件}` | `asset.bank.{舊收款帳戶}` |
   | 接收 | `handover_received` | `asset.bank.{新收款帳戶}` | `liability.deposit.{後繼案件}`、`liability.prepaid_rent.{後繼案件}` |

   - 預收租金與押金一起移交。ADR-0015 決議 9 只寫押金，本決議補上預收租金。
   - 一側只寫一筆分錄，所以 `UNIQUE (org_id, business_event_type, business_event_id)` 不會衝突。
   - 接收方確認接手時必須選收款帳戶，並經 `evaluateHolderRule` 檢查（ADR-0014 決議 13）。
   - 收款帳戶持有人變更時，必須附證據，檔案或說明擇一（P0-22 規則 4）。
   - 兩個業務函式放在 `ledger` 模組（ADR-0015 決議 13），由 F 線的票實作。

10. **應收期別。** 舊案件的期別不改。舊案件轉 `closed` 後，總覽與提醒都不計入。後繼案件產生生效日之後的期別，並把生效日前未足額的期別以剩餘金額帶入，標示來源是移交。屋主的累計逾期不因移交消失。

11. **生效處理。** 生效處理是 ADR-0016 決議 18 的第 8 條計時器，由 `scan-timers` 每日執行（ADR-0020）。生效日是當天時，接手後在同一請求內處理一次。交出側與接收側各一個交易，都以移交包 ID 保證冪等。

12. **擋下條件。** 純函式 `checkHandoverPreconditions(facts)` 回傳原因清單。有進行中的簽署任務時必須擋下（P0-22 規則 2）。接收方必須有涵蓋該租賃單位的有效委託管理案件，改自管時免查（P0-22 規則 1）。屋主確認、接手、生效處理三個時點都檢查。

13. **所有權讓與。** ADR-0015 決議 9 把所有權讓與後的接法交給 F 線。Phase 1 不做流程：使用者結案後，由新屋主開新案件。「買賣不破租賃」的處理待法務確認，列在 MIL-62。

## Considered Options

- **案件留在舊組織，新受託人以案件成員寫入：** 不用搬資料。但舊組織會一直看得到新資料，違反組織隔離。舊受託人失去寫入權也很難用 RLS 表達。
- **新增 `handed_over` 第八個狀態：** 清單上看得出移交。但要改 C 線的狀態機與 CHECK，`closed` 加案件事件已足夠。
- **複製合約列到接收方：** 後繼案件能沿用合約畫面。但會出現兩份「已完成」的同一合約，撤回與衍生規則也要例外處理。
- **協調列放在交出方組織：** 不用動 `control`。但接收方在 RLS 下讀不到，無法確認接手。
- **舊案件的期別改 `cancelled`：** 舊組織的清單較乾淨。但生效日前的欠費紀錄會從交出方消失。案件 `closed` 後也不再計入，所以不需要改。

## Consequences

- 每次移交都是兩個交易，中間有短暫的 `released` 狀態。worker 必須重試接收側。
- 後繼案件沒有合約列。讀合約欄位的畫面，在後繼案件上要改讀移交包的快照。
- 後繼案件的案件 ID 與舊案件不同。屋主的資產總覽以租賃單位 ID 串起前後案件。
- 舊組織的月報表在生效月之後不再包含該租賃單位。
- `control` 多一張表，ADR-0012 決議 5 的無組織脈絡入口多一個移交協調。
- **修正 ADR-0016 決議 10：** 跨組織時，移交會讓舊租賃案件轉 `closed`。
- **延伸 ADR-0015 決議 2、9：** 多兩個業務事件，預收租金也移交。
- 架構文件與 PRD 的待改項目列在 MIL-61。

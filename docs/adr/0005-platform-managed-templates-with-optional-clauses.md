# 範本由平台提供並版本化；條款彈性走「選用條款」而非自由編輯

正式版範本管理的定位（延伸 ADR-0004 的正式版範圍；MIL-14 決議）：範本**一律由平台提供**（依內政部住宅租賃定型化契約精神、經法務審閱），**不開放使用者自建範本或編輯條款全文**——法律品質由平台把關，也因此使用者端不需要範本編輯介面（範本維護歸平台營運方）。逐約彈性由三層組成：可編輯欄位＋平台提供的**選用條款**庫（逐約勾選，同樣經法務審閱）＋自由文字的「其他約定事項」欄。架構支援**多範本**（建約時選範本），首發僅一份住宅租賃範本，控制法務審閱成本。

範本與選用條款皆**版本化**：合約建立時綁定當下版本並快照條款內容，改版不回溯影響任何既有合約（含草稿）——與「合約引用物件即成快照」（見 `docs/domain-model.md`）同一套心智模型；草稿送簽前若範本有新版，提示可升版重建但不強制。

## Considered Options

- **開放使用者自建範本／編輯條款全文**：彈性最大，但法律風險轉嫁使用者、「經審閱範本」的產品保證失效，且需要完整範本編輯器。否決。
- **不做版本機制、只留最新版**：實作最簡，但改版會在使用者不知情下改動草稿內容。否決。

## Consequences

- 資料模型需新增 Template（含版本）與 Optional Clause（含版本）實體；Contract 增加對範本版本的引用與條款快照。
- ADR-0004 的「自由編輯條款劃入正式版範圍」一句由本決議收斂：正式版也**不**開放自由編輯，彈性上限即選用條款。
- 選範本步驟進入建約流程（首發單範本時可隱藏），由建約 UX（MIL-12）承接。

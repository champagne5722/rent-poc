# 合約＝寫死條款的固定範本＋填欄位；簽署區域由房東拖放決定

點點簽的簽名欄位以「頁碼＋座標」定位。若開放自由編輯條款，內容長度改變會使座標飄移，PoC 需處理動態座標計算，工程量不成比例。決定：合約內容採**單一內建範本＋可編輯欄位**（條款寫死、版面固定），而**簽署區域不寫死**——由房東在 PDF 預覽上拖放簽名框（指定簽署方／頁碼／座標），轉為 `field_settings` 送簽。這同時滿足「在系統中建立與編輯合約」與「系統要可以設定可簽署的區域」兩個需求，又避開動態版面的坑。

## Consequences

- 自由編輯條款（富文本→PDF）明確劃入正式版範圍，PoC 不做。
- 拖拉 UI 需處理瀏覽器像素座標 → PDF 點座標（原點在左下）的轉換，是整合筆記必記的眉角。

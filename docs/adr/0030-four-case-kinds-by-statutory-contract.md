# 案件依法定契約拆成四種，每種有自己的範本，簽約前的申請照法定名稱分兩種

舊設計只有租賃案件與委託管理案件，範本也只有兩份。屋主租給包租業者的合約記成自管的租賃案件。包租業者轉租的合約記成包租的租賃案件。兩者都借用住宅租賃契約的範本。條例與內政部公告把住宅租賃、委託管理、住宅包租、住宅轉租分開規定。使用者 2026-11-10 要求照法定名稱拆清楚，並能從物件看出有哪些案件。決議：案件拆成四種，名稱、當事人稱謂與範本都照法定契約。簽約前的申請也照法定名稱分成兩種。

本決議修訂 ADR-0016 決議 14、ADR-0018 決議 8、ADR-0023 決議 1、ADR-0029 決議 6、8，以及 PRD P0-09、P0-10。對照表在「修訂的舊決議」。法律假設待法務確認，集中在 MIL-62。調研筆記是 Q33。

## 決議內容

1. **四種案件。**

   | 案件 | 法定契約 | 當事人的法定稱謂 | 主辦組織 | 依據 |
   |---|---|---|---|---|
   | 租賃案件 | 住宅租賃契約 | 出租人、承租人 | 屋主的組織。代管時是代管業者 | 住宅租賃定型化契約應記載及不得記載事項 |
   | 委託管理案件 | 委託管理租賃住宅契約書 | 委託人、受託人 | 代管業者 | 條例第 28 條 |
   | 包租案件 | 住宅包租契約 | 出租人、包租業 | 包租業者 | 條例第 5 條第 2 項、第 29 條 |
   | 轉租案件 | 住宅轉租契約 | 包租業、承租人 | 包租業者 | 條例第 32 條第 3 項 |

   條例指租賃住宅市場發展及管理條例。

2. **「包租案件」改指屋主與包租業者之間的案件。**

   | 新名稱 | 舊名稱 | 程式碼現況 |
   |---|---|---|
   | 租賃案件，業務類型自管 | 自管租賃案件 | `lease`、`self_managed`，承租人不是包租業者 |
   | 租賃案件，業務類型代管 | 代管租賃案件 | `lease`、`managed` |
   | 委託管理案件 | 委託管理案件 | `management` |
   | 包租案件 | 自管租賃案件，承租人是包租業者 | `lease`、`self_managed`，承租人是包租業者 |
   | 轉租案件 | 包租案件 | `lease`、`master_lease` |

   讀 2026-11-10 之前的 ADR、PRD、票與程式碼註解時，照上表換讀。

3. **業務類型只留給租賃案件。** 租賃案件的業務類型是自管與代管。包租不再是業務類型。

4. **案件的資料有四個種類。** 案件種類在資料上有四個值，對應決議 1 的四種案件。既有的案件照決議 2 的對照表遷移。遷移的步驟留給 spec。

5. **案件之間的連結。**

   - 代管的租賃案件必須連到有效的委託管理案件（ADR-0023 決議 4，不變）。
   - 轉租案件必須連到有效的包租案件。包租案件必須涵蓋這個租賃單位，沒有就擋下。
   - 從物件看得到這兩層：委託管理案件與它底下的租賃案件，或包租案件與它底下的轉租案件。

6. **四種合約類型，各有範本。**

   | 合約類型 | 法定文件名 | 範本 |
   |---|---|---|
   | 租賃合約 | 住宅租賃契約 | 已有 |
   | 委託管理合約 | 委託管理租賃住宅契約書 | 已有 |
   | 包租合約 | 住宅包租契約 | 新做 |
   | 轉租合約 | 住宅轉租契約 | 新做 |

   - 新範本依內政部公告的應約定事項與應記載事項撰寫。
   - 新範本先標為未經法務審閱。未審閱的範本在正式金鑰下不能送簽，這是既有規則。
   - 現況確認附件跟著轉租合約。包租合約不加現況確認附件（ADR-0018 決議 8）。

7. **畫面與文件顯示法定名稱。** 畫面顯示合約類型時用法定文件名。合約文件與簽署欄顯示決議 1 的法定稱謂。「甲方」「乙方」只是平台內部對合約位置的稱呼，不印在文件上。

8. **簽約前的申請分兩種。**

   | 申請 | 對象 | 業者接受後建立 |
   |---|---|---|
   | 委託管理申請 | 代管業者 | 委託管理案件 |
   | 住宅包租申請 | 包租業者 | 包租案件 |

   - 兩種申請的流程、期限與規則相同，依 ADR-0029 決議 6、9。
   - 業者產生連結時指定申請的種類。同時登記代管業與包租業的業者，每個連結選一種。
   - 屋主在確認畫面看到的是對應的法定名稱。
   - 平台不另立統稱。ADR-0029 的「委託申請」讀作這兩種申請。

9. **社宅先不處理。**

   - 社宅包租包管的契約關係是包租案件加轉租案件。
   - 社宅代租代管的契約關係是委託管理案件加租賃案件，另有一份委託租賃契約。委託租賃契約屬於仲介業務，不在四種之內。
   - 社宅有自己的契約範本。第一階段不做社宅版的範本，也不做委託租賃契約。
   - 之後每種案件得加社宅版的範本，案件的種類不用改。
   - 現有的社宅旗標只用在押金帳戶規則，不變。

## 修訂的舊決議

| 舊決議 | 修訂後 |

| ADR-0018 決議 8 | 「業務類型維持自管」取消。這種案件是包租案件。簽章從嚴的規則不變 |
| ADR-0023 決議 1 | 主辦組織與允許的案件依決議 1。「屋主出租給包租業者的合約，業務類型是自管」取消 |
| ADR-0029 決議 6、8 | 「委託申請」分成委託管理申請與住宅包租申請（決議 8） |
| PRD P0-09 | 案件有四種。「包租案件專指轉租」改為轉租案件 |
| PRD P0-10 | 合約類型有四種，各有範本 |

## Considered Options

- **維持兩種案件，只改顯示的名稱：** 改動最小。但從物件看，屋主租給包租業者與屋主自己出租分不出來。範本仍借用住宅租賃契約，內容不符包租與轉租的公告。
- **共用「委託申請」：** 不用改名。但官方的包租文件不用「委託」。條例第 17 條寫的是「委託代管業或出租予包租業轉租」。
- **用「出租申請」統稱兩種申請（Q33 方案四）：** 資料只要一個詞，社宅的申請書也用這個詞。但使用者要求都用法定契約的名稱，不另立統稱。
- **社宅獨立成案件種類：** 社宅的流程與範本都不同。但契約關係與四種相同，差別在範本與計畫的流程。

## Consequences

- 「包租案件」的意思改變。舊文件、票與註解的「包租案件」指轉租案件。改名期間最容易混淆，改名的票必須加檢查。
- 簽章分流規則有兩列要改名與改條件。`lease.self_managed_lessee_master_lessor` 是包租案件，`lease.master_lease` 是轉租案件。席位與依據不變。
- 押金帳戶規則、點交證明、退還證明等用到業務類型的地方，都要改成看案件種類。
- 業務類型的 `master_lease` 值散在很多檔。改動要分批：先加新的案件種類，再逐批搬呼叫端，最後移除舊值。
- 包租合約得不經平台簽署（ADR-0018 決議 8）。屋主不上線時，包租案件由業者上傳紙本契約並經核對後成立，與 ADR-0029 決議 7 相同。
- 轉租的出租權源是轉租同意。包租合約在平台上完成時，能否直接當成轉租同意的文件，留給 spec。
- 住宅包租契約的公告只讀到 2019 年的版本。寫範本前必須確認現行版本。
- 住宅轉租契約與委託管理契約有至少三日的審閱期。住宅包租契約的公告沒有審閱期。平台怎麼處理，待法務確認。
- 代管業者能否替屋主招租與代簽租約，條例沒有寫。第一階段不提供，待法務確認。
- PRD P0-09、P0-10 的待改項目列在 MIL-61。

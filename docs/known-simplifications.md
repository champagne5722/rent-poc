# 已知簡化清單（PoC 刻意不做，正式版需補）

PoC 目標是驗證「建物件 → 擬約 → 設簽署區 → 點點簽依序簽署」流程可行（見 `GLOSSARY.md`），以下為刻意的偷懶，交付正式開發時需要重新評估：

## 產品範圍

- **無帳號與登入**：打開即房東視角，單一使用者。正式版需帳號系統與資料隔離。
- **無租客端介面**：租客只透過點點簽 email 簽署。正式版可能需要租客查看合約狀態的頁面。
- **甲方限房東本人**：未處理物業管理公司（操作者 ≠ 簽署人）的代理情境。
- **合約條款寫死**：範本一律平台提供、僅開放欄位編輯與選用條款勾選，無自由編輯條款；架構支援多範本但首發僅一份（ADR-0005）。
- **範本與選用條款是程式內常數**：內容版本化並在建約時快照進合約，但沒有維護介面（範本與條款維護歸平台營運 Admin 後台，規格明列範圍外）；平台改版＝改 `src/lib/clause-library.ts` 並進版號。
- **範本非法務審閱版**：條款為簡化示意，參考內政部住宅租賃定型化契約精神，未經法務審閱，**不可直接用於真實簽約**。
- **不支援**：改派簽署人、簽署期限與逾期提醒、附件（如屋況照片）、合約續約與到期標示（修約已支援：撤回 → 複製為新草稿並記衍生關聯，ADR-0006）。
- **畫面無法建立三位簽署人**：簽署模組支援任意人數的簽署序列，合約狀態也有「待執業人員簽」。但送簽畫面只組乙方與甲方兩位，簽署區編輯器也沒有執業人員的簽署區域。三位簽署人的路徑目前只由測試經簽署模組驗證（MIL-52 範圍外，見 P0-12）。
- **簽署連結無簽署人驗證**：簽署連結顯示在無 auth 的合約頁，任何能開頁面的人都可代簽。正式版應做簽署人身分驗證（點點簽有 `verify_methods` 可用 email/SMS OTP）。

## 技術面

- **SQLite 單檔**、無正式 migration 工具：schema 以 `ensureSchema`（`CREATE ... IF NOT EXISTS`＋`PRAGMA` 檢查後補欄位）向前相容，加表加欄免刪庫。刪欄刪表要在 `ensureSchema` 裡先檢查是否存在，必要時先回填（前例：MIL-60 移除合約的任務編號欄位與 `contract_files` 表）。改欄型別仍＝刪 `data/rent-poc.db` 重來。
- **測試僅涵蓋純邏輯 seam**（vitest 230+：狀態機與歷程事件、條款快照、列表／工作台／wizard／詳情頁的選擇邏輯、PDF 版面與簽署區幾何），route handler 與 UI 靠手動與 API 冒煙測試。
- **簽署完成導回網址在本機開發指向 localhost**：簽署連結的 `redirect_url` 優先用 `APP_ORIGIN`，沒有設定時用系統當下 origin。demo 環境已設定 `APP_ORIGIN`，但導回後會看到 Basic Auth 登入框。正式版需正式登入。
- **demo 環境只有 Basic Auth 與單一 SQLite 寫入端**：換版時可能遺失數十秒的寫入，不得放真實個資，pilot 前必須完成 PostgreSQL 遷移（ADR-0011）。
- **PDF 整字型內嵌**（6.8MB 字型 → 4.3MB PDF），未做字型子集化（見整合筆記踩坑 1）。
- **Embedded signing 未做**：簽署體驗在點點簽頁面，非站內（ADR-0003）。
- **輪詢更新狀態**（前端每 5 秒），未做 SSE/WebSocket 即時推播。
- **錯誤處理陽春**：點點簽 API 失敗直接顯示錯誤訊息，無自動重試（例外：完成時的文件保存有失敗記錄與手動補抓）。
- **物件刪除未擋關聯合約**（合約存快照所以不會壞，但列表上物件會消失）。
